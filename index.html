Unit Testing in R

How to write down what your R functions should do, as code the computer can check, using the testthat package. For data science students who can write a function and a dplyr pipeline and have never written a test.

Each lesson takes 20 to 30 minutes, teaches one skill, and ends with a short quiz. You write every test by hand. The examples are the small data-cleaning helpers you already write: rescaling a column, tidying column names, parsing money, summarising by group.

Lessons

  1. 1 Your first expectation Turn a glance at the console into expect_equal(). Read a pass and a failure.
  2. 2 test_that() and test files Name your tests, give them a folder, and run them all with one line.
  3. 3 Choosing the right expectation The handful of expectations you need, and how to test a function that returns a data frame.
  4. 4 Edge cases, errors and bugs Missing values, constant columns, wrong types. Catch a real bug with a failing test, then fix it.
  5. 5 From project to package Move your functions and tests into a package and run them with devtools::test().

Before you start

  • R 4.1 or later (the examples use the native pipe, |>), with RStudio or Positron.
  • These packages: install.packages(c("testthat", "dplyr", "tibble")). Lesson 5 adds devtools and usethis.
  • You should be comfortable writing a function and using group_by() and summarise(). No testing experience is assumed.

How to use these pages

  • Type, don't just read. Each lesson has a “Try it” section. The skill is in your fingers, not on the page.
  • Take the quizzes from memory. Lessons 2 to 5 open with two questions about the lesson before. They are meant to be a little hard; recalling something is what makes it last.
  • Come back. One lesson a day works better than five in a row. Retake a quiz a few days later; the answers are reshuffled each time.
  • Ask. When something is unclear, take the exact code and message to your instructor, a classmate, or an AI assistant.
