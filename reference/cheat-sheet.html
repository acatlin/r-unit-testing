Anatomy of a test

Expectations are grouped into tests; tests are organised in files. A passing expectation is silent. (Lesson 1, Lesson 2)

Habits

  • Work out the expected value yourself. Never compute it by calling the function under test.
  • Small inputs. Three rows you can check in your head are worth more than three thousand you cannot.
  • One behaviour per test, with a description that says what should happen.
  • Each test builds what it needs. No test depends on another.
  • Walk the edge cases: missing values, all values the same, a single value, empty input, the wrong type.
  • Bug found? Test first. Write a test that fails, fix the code, run all the tests.
  • Prefer the specific expectation to expect_true().
  • See every test fail once. A test that has never failed has not shown it can.
