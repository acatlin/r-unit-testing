Glossary

The course's vocabulary. Each term is used in exactly this sense on every page.

Actual
What your code really returned. The first argument of most expectations. Lesson 1
Description
The first argument of test_that(): a sentence saying what the code should do. It is printed when the test fails. Lesson 2
DESCRIPTION
The settings file at the top of a package. It lists the packages yours depends on and sets the testthat edition. Lesson 5
Edge case
An input at the boundary of what a function was written for: missing values, an empty vector, a constant column, the wrong type. Lesson 4
Edition
A version of testthat's behaviour. The third edition is current. A plain project selects it with local_edition(3) at the top of each test file; a package selects it in DESCRIPTION. Lessons 2, 5
Expectation
A single check: a call to a function whose name starts with expect_. It is silent when it passes and reports a failure when it does not. Lesson 1
Expected
What the code should return, worked out by you and typed into the test. The second argument of most expectations. Lesson 1
Failure
An expectation whose actual and expected values disagree. Either the code or the test is wrong; the report helps you decide which. Counted under FAIL. Lessons 1, 2
Happy path
Ordinary, well-formed input producing an ordinary result. The first thing to test, never the only thing. Lesson 4
Package
R's standard way to bundle functions, their tests and their settings in one folder with a fixed layout. Lesson 5
Regular expression
A text pattern. expect_error(), expect_warning() and expect_match() take one and check that a message or string matches it. A plain phrase such as "must be numeric" is the simplest kind. Lessons 3, 4
Test
One call to test_that(): a description plus one or more expectations about a single behaviour. Lesson 2
Test file
An R script in tests/testthat/ whose name starts with test-. It holds the tests for one file of functions. Lesson 2
testthat
The R package this course uses for unit testing. Lesson 1
Tolerance
The small numeric difference that expect_equal() ignores, so that floating-point noise does not cause failures. expect_identical() has none. Lesson 1
Unit test
A check, written as code, that one small piece of a program (usually one function) behaves as intended. Lesson 1

Definitions follow the usage in R Packages (2e) and the testthat documentation. See also the cheat sheet.
